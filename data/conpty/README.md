# Bundled ConPTY

`data/conpty/` holds the pinned
[`Microsoft.Windows.Console.ConPTY`](https://www.nuget.org/packages/Microsoft.Windows.Console.ConPTY)
binaries used by the `coffer` CLI on Windows.

## Layout

```
conpty.lock                 pinned package version + SHA-256
LICENSE                     Windows Terminal MIT license
NOTICE.md                   Windows Terminal third-party notices
<x64|arm64|x86>/conpty.dll       generated by fetch_conpty.sh
<x64|arm64|x86>/OpenConsole.exe  generated by fetch_conpty.sh
<x64|arm64|x86>/SHA256SUMS       generated by fetch_conpty.sh
```

The binaries are **not** committed. Fetch them with:

```sh
./scripts/fetch_conpty.sh            # host architecture
./scripts/fetch_conpty.sh --arch all # all architectures, for `make dist`
```

## Why bundle OpenConsole?

`conpty.dll` looks for `OpenConsole.exe` next to itself (or in an
`x64/`, `arm64/`, `x86/` subdirectory), and falls back to the system
`conhost.exe` if it is missing. The bundled OpenConsole is the ConPTY
rewrite that passes DCS (sixel), APC (kitty/Lottie) and unknown OSC
sequences through unmodified; the system conhost strips DCS and APC.
`ConptyCreatePseudoConsole` still succeeds when OpenConsole is absent,
so the loader checks for it explicitly.

## Updating

`scripts/update_conpty.py` queries the NuGet flat-container index,
selects the latest stable version, updates `conpty.lock`, verifies the
package hash and (on Windows) the Authenticode signature, then fetches
all architectures. Run it from a clean tree and commit the lock change.

Preview builds are opt-in:

```sh
./scripts/update_conpty.py --preview
```
